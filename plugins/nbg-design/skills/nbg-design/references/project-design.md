# Project Design

## Overview
This project contains the assets of a presentation design system inspired by the brand image of the National Bank of Greece (NBG), plus the supporting configuration artifacts for using Pi Agent to create presentations in that style.

### Portable deterministic Pi context configuration
- Decision: Keep `config/pi-agent-nbg-design.yaml` as the single shared Pi context file, but make all project-internal paths repository-root-relative and remove machine-specific checkout roots from shared runtime/setup configuration.
- Rationale: The portability investigation found that the current project is a lightweight design-system/context artifact repository, not a packaged application. A repository-relative config model plus deterministic setup documentation fixes the known local-folder coupling without introducing unnecessary package, container, or local override systems.
- Path semantics: Pi `@file` relative paths resolve against the shell current working directory. Deterministic usage therefore requires running Pi commands from the repository root, or a future wrapper that changes to the repository root before invoking Pi.
- Runtime boundary: The YAML is included as prompt/context text. Pi does not parse it as native settings, expand variables, or automatically read nested file references listed inside it.
- Setup guide: `docs/design/configuration-guide.md` documents prerequisites, configuration source priority, required values, path-resolution rules, validation checks, and the portable Pi command.
- Source evidence:

### HTML presentation overlap-protection guardrail
- Decision: `SKILL.md` and `config/pi-agent-nbg-design.yaml` now require generated NBG HTML presentations to protect against unintended internal element overlaps, not only viewport overflow.
- Rationale: The regression deck `agentic-engineering-nbg-executive-presentation.html` showed that a slide can fit the browser viewport while still having collisions inside the 1920×1080 artboard. Slide 2 overlapped a board-level implication card with the bottom three-card row; slide 3 overlapped the top card row with lower question cards.
- Required pattern: Reserve separate zones for title/header, body content, card rows/grids, bottom callouts, footer/logo, and page-number elements; keep clear spacing between content groups; verify absolute-positioned row/callout bounding boxes before finalizing.
- Remediation pattern: If content cannot fit safely, reduce copy, simplify or resize components, change the grid structure, or split content across slides. Do not hide overflow or layer opaque elements over content to mask a collision.
- Quality checks: Future HTML outputs must inspect screenshots at 1366×768 and 1440×900 for card-to-card, callout-to-card, shape-to-content, logo/footer-to-content, and page-number collisions; any overlap requires layout revision and repeated screenshot validation before delivery.

### HTML deck PDF export (skill v1.3.0)
- Decision: A PDF deliverable is always **exported from the finished, verified HTML deck** by the bundled zero-dependency script `scripts/export-pdf.mjs`; it is never authored separately, re-laid-out for paper, or assembled from screenshots. `pdf` joins `html` (default) as an accepted output format.
- Rationale: The requirement is "converted to PDF without changes in aesthetics". Printing the deck with the same browser engine that renders it, at the slide's own box (1920×1080 px = 20 × 11.25 in, zero margins, backgrounds forced, scale 1), keeps typography, palette, spacing, logos and photography identical and leaves the text vector/selectable. Every other route (browser Save-as-PDF at A4/Letter with headers, `window.print()`, Office round-trips, stitched screenshots) re-flows or rasterises the design.
- Mechanism: Headless Chrome/Chromium/Edge is driven over the DevTools protocol through `--remote-debugging-pipe` (no npm dependency). A shim evaluated in the page lifts only the host layer — navigation toggles (`.active` / `.hidden` / inline `display` / `[hidden]`), viewport-fit wrappers (scaled `#deck` / `.slide-wrap`, fixed `#stage`, flex centering), non-slide chrome — makes every top-level `.slide` visible in flow, jumps animations/transitions to their end state, forces `print-color-adjust: exact`, waits for fonts/images, then calls `Page.printToPDF` with `printBackground`, `preferCSSPageSize`, page size = measured slide box. A slide's own CSS/size/copy is never touched; slides of another size are reported, not resized.
- Built-in gate: page count must equal slide count and every slide box must equal the page box; otherwise the exporter exits 1 (the PDF is still written for diagnosis). Exit 3 = no browser on the host → deliver the HTML and the one-line command to run elsewhere.
- Shared code: the browser locator moved to `scripts/lib/find-browser.mjs`, used by both `screenshot-deck.mjs` and `export-pdf.mjs`. `screenshot-deck.mjs` also gained a generic in-place slide isolation (works for `.hidden` toggles and stacked decks), an exact-token slide count, and injection before the last `</body>`.
- Verification (2026-09-03): three real decks produced with this skill (15, 11 and 17 slides; `.active`-toggle, stacked-scroll and `.hidden`-toggle hosts) exported with pages = slides; pdftoppm renders pixel-diffed against 1920×1080 browser screenshots show at most 0.16 % of pixels with a solid difference (anti-aliasing of text edges only). Record: `docs/nbg-design-docs/verification.md` in the development workspace.
- Configuration: `config/pi-agent-nbg-design.yaml` → `presentation_workflow.expected_agent_behavior` (PDF rules), `optional_user_inputs_with_defaults` (accepted formats), `presentation_generation_rules.pdf_export`, `visual_verification.required_for_output_formats` (+ `pdf`), `quality_checks`.

### In-deck right-click "Export to PDF" menu (skill v1.4.0)
- Decision: Every delivered HTML deck carries a self-contained right-click menu whose **Export to PDF** item produces the same one-page-per-slide PDF as `scripts/export-pdf.mjs`, for viewers who have only the HTML and a browser. `scripts/add-pdf-menu.mjs` inlines it; `verify-deck.mjs --strict` requires it (`--no-pdf-menu` only when the user declined it).
- Rationale: A delivered deck runs standalone from `file://` with no Node available. The browser's own print engine is the only PDF producer there, so the deck must prepare its own print layout — and it must be the *same* layout the CLI produces, or the two PDFs would differ.
- Mechanism: The print-layout shim moved to `scripts/lib/print-layout.js` (plain browser JS) and gained a registry so `nbgRestorePrintLayout()` can undo every class/inline-style/attribute change and re-dispatch `resize` for the deck's viewport-fit code. `scripts/lib/pdf-menu.js` adds the menu (contextmenu → NBG-inspired panel; Escape/outside click closes; links/form fields keep the native menu), and around `window.print()` it runs prepare → print → restore. `beforeprint`/`afterprint` hooks make Ctrl/Cmd+P and the browser's Print command faithful too; Chrome fires the same events around DevTools `Page.printToPDF`, so a driver that manages the layout itself (the CLI exporter) sets `window.__nbgPdfExternal = true` to keep the hooks idle. The injected block's id (`nbg-pdf-menu-script`) deliberately differs from the runtime menu element (`nbg-pdf-menu`).
- What the viewer does: right-click → *Export to PDF* → the print dialog opens with the page's `@page { size: 1920px 1080px; margin: 0 }` → choose *Save as PDF* (Chrome/Edge). Backgrounds are forced by `print-color-adjust: exact`; zero margins suppress browser headers/footers.
- Shared code: `scripts/lib/cdp.mjs` (DevTools client: launch, open page, navigate, evaluate, print, count pages) is used by `export-pdf.mjs` and by the development round-trip test.
- Verification (2026-09-03): on the three real decks, the native print path (no driver preparation, hooks only) yields pages = slides, the DOM (`outerHTML`) and computed transforms are byte-identical after the round-trip, and the PDFs pixel-match the browser renders exactly like the CLI export (≤ 0.16 % solid difference). `docs/nbg-design-docs/verification.md` in the development workspace.

### In-deck text editing and "Save edited copy" (skill v1.5.0)
- Decision: The in-deck menu (renamed `scripts/add-deck-menu.mjs` / `scripts/lib/deck-menu.js`, block id `nbg-deck-menu-script`) lets viewers edit any text on a slide in place — double-click, or right-click → *Edit text* — keep the edits across reloads, download the deck with them applied (*Save edited copy*), or drop them (*Discard edits*). Layout, images, colours and structure are deliberately not editable.
- Rationale: A standalone `file://` deck cannot write to itself, so "edit in place" needs three parts: an editing surface that cannot damage the design, a memory that survives a reload, and a way to hand the result back as a file. Text-only editing keeps the NBG-inspired design system intact; the saved copy is the deliverable path.
- Editing surface: the whole text block (inline accent spans inside a title stay intact) becomes `contenteditable="true"` — not `plaintext-only`, whose UA `white-space: pre-wrap` re-flowed titles while editing. Formatting commands, rich paste and drops are blocked in `beforeinput` (paste inserts plain text); Enter applies, Esc cancels, Shift+Enter inserts `<br>`; original descendants are tagged during the edit and every element the browser wraps around typed text is unwrapped on commit, so the committed markup is the original inline markup plus text. Deck shortcuts are suppressed while editing.
- Persistence: edits are `{ path, original, html }` (child-index path from the root) in `localStorage` under `nbg-deck-edits:<pathname>#<title>`; re-applied on load, entries whose original no longer matches are dropped.
- Saved copy: a pristine `outerHTML` snapshot is taken when the inlined script runs (after the deck's own scripts, before any runtime element of ours and before stored edits are re-applied); `DOMParser` applies the edits by path (unique-markup fallback) and the result downloads as `<name>-edited.html` — still self-contained, still carrying the menu, loading exactly like the original.
- Boundaries: the CLI exporter prints the file on disk; a PDF of an edited deck is made from the saved copy. `verify-deck.mjs --strict` requires the v2 block (`--no-deck-menu` only when the user declined it) and warns on the v1.4 PDF-only block, which `add-deck-menu.mjs` upgrades in place.
- Verification (2026-09-03): on the three real decks, `test_scripts/deck-menu-roundtrip.mjs` covers double-click editing, shortcut suppression, blocked formatting, wrapper clean-up, Enter/Esc, persistence across reload, the saved copy (passes `verify-deck.mjs --strict` and `export-pdf.mjs`, edit visible on page 1), discard, and both PDF paths with DOM/transform identity after restore. `docs/nbg-design-docs/verification.md` in the development workspace.

### In-deck shape resizing and moving (skill v1.6.0)
- Decision: The in-deck menu gains *Resize / move shape*: a selection frame with eight handles on the card, photo panel, image, decorative block or text block under the pointer. Drag handles to resize (Shift keeps proportions), drag inside to move, arrows nudge (Shift 10 px), Alt+arrows resize, Tab selects the enclosing shape, Esc/Enter/click outside finishes; *Reset shape* restores one element. Edits are `{ path, kind: 'style', original, value }` records — the same persistence, *Save edited copy* and *Discard edits* as text edits.
- Rationale: A viewer who can fix a word should also be able to fix a card that is too narrow or a photo panel that needs nudging, without asking for a regeneration. Restricting the change to inline geometry keeps the design system's colours, typography and structure intact and keeps every change reversible.
- Mechanism: "shape" = positioned element, or one with a background, border or shadow, or an image; otherwise the text block. Pointer deltas are divided by the slide's current scale (`getBoundingClientRect().width / offsetWidth`) so the artboard coordinates are exact at any viewport size. Resizing a positioned element first pins its top-left corner (`left/top` explicit, `right/bottom: auto`) — otherwise a right/bottom-anchored element slides when its size changes — then writes `width/height` in the element's own `box-sizing`. Flow elements get only the east/south/corner handles; moving one sets `position: relative` offsets. The frame (`#nbg-shape-box`) is a fixed-position overlay outside the slides, so the print layout hides it; `prepare()` deselects before printing.
- Gate: `verify-deck.mjs --strict` now also warns when the deck's block is older than the version the skill ships (read from `scripts/lib/deck-menu.js`), so re-delivered decks get the current menu.
- Verification (2026-09-03): `test_scripts/deck-menu-roundtrip.mjs` on the three real decks — selection frame with eight handles on the cover photo panel; south-east drag at a 0.71 scale grows the box by exactly the scaled delta with the position unchanged; drag inside moves it; north-west drag keeps the opposite corner; arrow/Shift/Alt nudges; Reset; persistence across reload; saved copy carries the inline geometry; both PDF paths unchanged. One sample deck (`nbg-design-skill-guide-deck.html`) mis-fits a 1366×768 viewport (it centres the unscaled box — the very pattern the skill forbids), so the test uses the full artboard for it.

### In-deck text formatting toolbar (skill v1.7.0)
- Decision: While a text element is being edited, a toolbar floats above it: Bold / Italic / Underline / Strikethrough, A− / A+ and an exact px size, font family, text colour, alignment, Clear, Done. A selected run gets semantic `<b>/<i>/<u>/<s>` tags (Chrome's `execCommand` with `styleWithCSS` off; an "un-bold inside a bold block" arrives as a `<span style="font-weight: normal">` and is kept when its style holds only weight/style/decoration); with no selection the whole block toggles via inline style. Size, family, colour and alignment are always block-level inline style.
- Brand guardrails: font families are limited to the design system's stacks (Aptos, Inter, Helvetica, Arial, Georgia, Times New Roman, Courier New, Default) and colours to the NBG palette (deep teal, teal, bright cyan, electric cyan, black, grey, cream, white, Default). A viewer can emphasise and resize text but cannot leave the palette or bring in arbitrary fonts.
- Mechanism: block formatting edits the element's `style` attribute and is recorded as a `style` edit next to the `html` edit (same records as shape geometry — one `style` record per element, first original kept); Esc restores both. *Clear* returns the block to the inline style it had before any formatting (this session's or an earlier saved one) and removes the selection's tags — it never strips the design's own inline properties. A first font-size change also sets a unitless `line-height` equal to the current ratio when the design fixed line-height in px, so enlarged text does not overlap. `pointerdown` on the toolbar is default-prevented so the editable keeps focus and selection; the size field and family select save/restore the selection around their own focus; the live selection is authoritative whenever the editable is focused. Shortcuts: Ctrl/Cmd+B/I/U (collapsed caret → whole block), Ctrl/Cmd+Shift+> / <.
- Verification (2026-09-03): `test_scripts/deck-menu-roundtrip.mjs` on the three real decks — toolbar appears; clicking it keeps the session; bold on a selection wraps the run (v3's already-bold title gets the un-bold span, kept on commit); italic/A+/Ctrl+Shift+>/exact 40 px/Georgia/bright cyan/centre/underline as inline style; toolbar state reflects it; Clear returns to the authored style; Enter records `html` + `style`; Esc restores both; persistence across reload; saved copy carries the formatting; discard restores. Defects found and fixed on the way: Clear stripped the authored `font-size`; a stale saved selection overrode the live one; un-bold spans were unwrapped.

### Selection-level formatting, movable toolbars, shape toolbar (skill v1.8.0)
- Decision: Every text-toolbar control now applies to the selected text when there is a selection and to the whole block only when there is none (the user's correction of v1.7.0). Toolbars can be dragged by a grip and stay where they are put. A shape toolbar accompanies the selection frame: X / Y / W / H, fill, border, corner radius, opacity, shadow, Reset, Done.
- Mechanism (text): size, family and colour on a selection use `wrapSelection()` — the text nodes intersecting the range are split at the boundaries and each run is wrapped in a `<span style>` (reusing a span that already wraps just that run); the kept-span rule now covers `font-size`, `font-family`, `color` and `line-height` in addition to weight/style/decoration. Clear on a selection removes its tags and spans; Clear with no selection returns the block to its authored style.
- Mechanism (panels): `.nbg-panel` shared styling; `makeMovable()` adds the `⋮⋮` grip (pointer capture drag, position remembered per panel until the grip is double-clicked); `placePanel()` docks above the anchor or uses the remembered position. Panels hide through `.nbg-panel[hidden]{display:none!important}` — the bug behind "Done does not hide the toolbar" was the panel's own `display:flex` beating the `hidden` attribute.
- Mechanism (shape toolbar): geometry fields go through the same `setPos`/`setSize` as the handles (top-left pinned on resize), cosmetics through `shapeStyle()`; every change updates the element's single `style` record. Fill/border colours are the NBG palette; a new border defaults to solid deep teal. Keys typed in the toolbar's inputs are not deck shortcuts; clicks on it do not deselect the shape.
- Verification (2026-09-03): `test_scripts/deck-menu-roundtrip.mjs` on the three real decks — colour on the last three characters wraps only that run (block colour unchanged), size 40 lands on the same span (block size unchanged), Clear on the selection removes only that span; the text toolbar moved by a real grip drag (+120, +60) stays put across relayouts; a real click on Done hides the toolbar (computed `display: none`); the shape toolbar shows the current geometry, W/X fields resize/move, fill/radius/opacity/border/shadow land as inline style and are reflected back, Default choices remove them, the panel moves by its grip, Done deselects; saved copies still pass the strict gate and the exporter.

### Multi-selection, ordering, aligning, distributing, grouping (skill v1.9.0)
- Decision: The in-deck menu works on several shapes at once — text blocks, cards, panels and images alike. Shift+click adds/removes a shape, Shift+drag draws a selection box, Ctrl/Cmd+A selects every top-level shape of the slide, Ctrl/Cmd+click picks one shape alone; the menu offers *Add to selection* / *Remove from selection* / *Select all shapes*. The frame spans the selection, dragging moves all, handles scale all proportionally, the style controls apply to all. A second toolbar row arranges: Order (front / forward / backward / back), Align (six ways) and Distribute (two axes) relative to the selection or to the slide, Group / Ungroup.
- Rationale: A viewer fixing a slide usually adjusts a row of cards, not one card: line them up, spread them evenly, move them together, put a badge in front of a photo. These are the slide-editor operations people expect once resize/move exists, and doing them by hand through X/Y fields is error-prone.
- Mechanism (selection): `sel[]` plus a primary element; `setSelection()` expands groups and sorts in document order; `slideShapes(slide)` lists the top-level shapes (an element `resolveShapeTarget` maps to itself, with no such ancestor, excluding layers that fill ≥ 98 % of the slide — the backdrop); Shift+click and the rubber band work with the top-level shape containing the click (`topShape`), Ctrl/Cmd+click and the menu with the precise element (`pick`). Modifier gestures are default-prevented and the following `click` is swallowed so the deck's own click handlers never see them; a right-click no longer deselects, so the menu can add to the selection.
- Mechanism (geometry): everything is computed on screen rects and converted through the slide scale, so members in different offset parents behave alike; `shift()` moves a positioned element absolutely and a flow element by relative offsets; `scaleMembers()` keeps each member's fraction of the union box; `withRecords(els, fn)` records one `style` edit per element that actually changed. `setPos()` now pins the width/height of an element that was sized by its right/bottom anchors (an `inset` panel, a shrink-to-fit text block) — a latent v1.6 defect: moving such a panel collapsed it.
- Mechanism (order): inline `z-index` only, never DOM re-ordering (edit records are child-index paths, so restructuring would invalidate every earlier record). Siblings are ranked by effective layer (`zKey`: negative < in-flow 0 < positioned auto/0 = 0.5 < positive, ties in document order); the target takes the next free tier, one-step moves push neighbours only on a collision; a static element gets `position: relative`; a negative index makes the parent a stacking context (`isolation: isolate`) so the element does not sink below the slide background. Multi-selections keep their own relative order (bottom-most first when raising, top-most first when lowering).
- Mechanism (group): logical, not structural — members carry `data-nbg-group="<id>"`, recorded as a third edit kind `group` (`current`/`apply` generalised), so groups persist per browser, land in the saved copy, survive a reload and are removed by Discard; selecting a member selects the group; grouping a selection that contains groups merges them.
- Mechanism (stack picker, added on the user's report that a nested shape "selects the outer one"): a click can only land on one level — right-click resolves to the innermost boxed element (a text block inside a card gives the card), Shift+click and the selection box to the outermost. `shapeStack(x, y)` lists the shape candidates (boxed elements or text blocks) among `elementsFromPoint`, front-most first; the menu renders them as *Select at this point* items (click = alone, Shift+click = add); the toolbar's Stack select offers `ancestorShapes` + the selected element + `childShapes`; Ctrl/Cmd+click on the same spot cycles outward (`pickAtPoint`); Tab selects the enclosing shape, Shift+Tab the child under the last pointer position. The default targets of a click were kept so v1.6–v1.8 behaviour is unchanged.
- Per-slide discard (user request): *Discard changes on this slide* restores the records whose element lives inside the slide under the pointer (`slideAtPoint`: the slide hit by the right-click, else the one at the viewport centre, else the first visible), newest first, and drops them; the hint states the slide number and its change count; *Discard edits* keeps clearing every slide. API `edit.discardSlide`, `edit.listFor`, `edit.slideAt`.
- HTML panel (user request, third follow-up): "see the HTML of what I selected, and navigate both ways". Tree rows are keyed by the same child-index paths as the edit records, so the mapping element ↔ row is exact and cheap; the panel follows the primary selection or the text being edited (`codeFollow`), re-renders on records and on a body-wide `MutationObserver` (our own elements ignored) so deck-driven slide switches are picked up without polling; a row click goes through `selectSolo` (the exact element, any level), so the tree is also a stack picker. **Editable source (the user's explicit decision after the guardrail concern was raised)**: the Code tab shows the element's exact source (no pretty-printing — formatter whitespace would become text nodes and could shift inline layouts) and Apply records the result through the existing pipeline: `style`, `group`, `html` records plus a fourth kind `attrs` (the remaining attributes as sorted JSON, reconciled by `applyAttrs`), so source edits persist, reload, land in the saved copy and are discarded like every other edit. Guard rails kept: exactly one root element of the same tag (paths stay valid), scripts / iframes / objects / `on*` handlers / `javascript:` URLs stripped; descendant records are kept so earlier edits inside the element replay in order. The panel is the one place a viewer can leave the palette and font stacks, documented as such in SKILL.md.
- Outline tab (skill v1.10.0, block v7 — user request, fourth follow-up: "a tree view of the page structure to select one or more items"): the Tree tab already listed everything, but as raw HTML; the Outline shows only shape candidates nested by containment (`childShapes` recursion), with readable labels and a checkbox per row, so multi-selection is explicit and the page highlights follow. It surfaced a gap that had been latent since multi-selection: nothing stopped a container and its content from being selected together, in which case a move applied twice — `setSelection()` now keeps the outer element only and says so.
- UI: the shape toolbar became two explicit flex rows inside a column-direction panel (a wrapping single row would take the full viewport width, because a wrapping flex container's intrinsic width is the sum of its items); `placePanel()` falls back to "just inside the anchor's top edge" when a panel fits neither above nor below (the two-row panel otherwise covered the bottom handles); a right-click on the frame of a single selection refers to that shape even when a sibling overlaps the point. Arrange buttons use small inline SVG icons; the reference select (`to selection` / `to slide`) is disabled for a single shape.

### Toolbar visibility modes and selection-driven toolbars (skill v1.12.0, block v8)
- Decision (user request): a *Toolbars* section in the right-click menu where the viewer decides which toolbars stay visible or hidden, with the toolbars' own ✕ reflected there; and every toolbar adapts whenever the slide or the selection (text, image, shape) changes.
- Mechanism: three modes per toolbar — `auto` (with the selection, the previous behaviour), `on` (pinned; idle state when nothing applies), `off` (closed until shown again) — persisted per deck; `syncToolbars()` is the single show/hide path, called on every selection, edit and slide change, so a toolbar's content is always derived from the current selection. The text toolbar gained a no-edit-session mode: with a text block selected as a shape it applies block-level formatting to every selected text block (`formatBlocks`), recorded as `style` edits like the shape toolbar's changes. A document-level observer detects the deck's own slide switches (class / style / hidden changes outside our elements, plus scroll, hash, popstate, resize and transitionend) and drops a selection whose slide left the screen; the structure panel's slide is the one on screen whenever the element it followed is off-screen (a user-reported defect: it used to stay on the last selected element's slide).
- Rationale: pinned toolbars suit viewers who make many small changes; the ✕ / menu tick pairing gives one obvious place to recover a closed toolbar; deriving every toolbar's content from the selection removes the stale-toolbar states that appeared once several toolbars could coexist. Shape and text toolbars avoid covering each other (the shape toolbar slides below the text toolbar).
- Verification (2026-09-03): round-trip test on the three real decks — menu ticks mirror visibility, untick hides and keeps hidden across selections, tick pins and the toolbar idles after Escape, ✕ unticks, Automatic restores; a selected text block gets B / size / colour as inline style with one record and Clear restores it; pinned text toolbar idles; hiding the slide clears the selection and the toolbar; modes persist.

### AI assistant panel (skill v1.13.0, block v9)
- Decision (user request): a toolbar that submits a request to an LLM, supported — each behind a checkbox — by a screenshot of the current slide, the slide's complete source, the selected element's source and any image in the viewer's clipboard; a drop-down of prompts (built-in and the viewer's own, editable and deletable, with short names) plus free additional instructions; the reply either shown in the panel or applied as the replacement of the selected element; providers Anthropic, Azure-hosted Anthropic, OpenAI-compatible, Azure OpenAI and DeepSeek, with the selection stored in the browser.
- Endpoint and key (option chosen by the user, 2026-09-03): entered in the panel's Settings and kept in that browser's storage only (the key optionally for the tab only) — never in the deck file, never baked in by the injection script. The page calls the endpoint directly; a provider that rejects browser calls needs a gateway. No fallbacks: a missing provider, URL, model or key blocks the request with a message; "Standard values" fills a provider's fixed endpoint and model only on the viewer's click.
- Screenshot (user's choice): tab capture with the current-tab preference, our UI hidden during the frame, cropped to the slide; not the in-page rasteriser. Clipboard image: the paste event on the request box (no permission), a drop target, and the async Clipboard API as a second path.
- Mechanism: the request carries a fixed system prompt (deck context, palette, font stacks, how attachments look, the reply-mode instruction) and one user turn: images first (screenshot, clipboard image), then the text (prompt, instructions, sources). Embedded images are replaced by `nbg-image:N` placeholders in every source and restored when a reply is applied, so photos never cost tokens. "Replace" reuses the Code tab's apply path (`applySource`: one root of the same tag, sanitised, recorded) and offers Undo.
- Rationale: the checkboxes let the viewer control cost and privacy per request; prompts with short names make repeated tasks one click; the placeholder scheme keeps the sources small and the round trip lossless; sharing the apply path keeps every AI change a normal, reversible, saved-copy-able edit.
- Verification (2026-09-03): round-trip test on the three real decks through hooks (stub capture, stub endpoint): missing settings refused one by one, key scopes, prompt add / select / edit / delete with persistence, paste attach, the five providers' URLs / headers / bodies, image blocks and placeholders, reply shown, replace applied with placeholders restored, Undo, wrong-tag and multi-selection refusals, HTTP error surfaced, ✕ / mode persistence. ### Detachable panels (skill v1.14.0, block v10)
- Decision (user request, 2026-09-04): the floating toolbars can be moved outside the browser window. ### Per-deck rebuild script (skill v1.16.0)
- Decision (user request, 2026-09-05): every delivered presentation is three files — `<deck>.html`, `<deck>.pdf` and `<deck>.rebuild.mjs`. The third is written by `scripts/write-rebuild-script.mjs` after `add-deck-menu.mjs` and is the way a deck handed over earlier receives a newer version of the editing tools it embeds (the inlined `nbg-deck-menu-script` block: menu, toolbars, structure panel, assistant, print layout) without being regenerated: it replaces only that block (through the skill's own `addMenu`, with the configuration the deck was delivered with), runs `verify-deck.mjs --strict` and re-exports the PDF with `export-pdf.mjs`; `--check` only compares the embedded block version with the skill's.
- Mechanism: the generator records, as plain JSON at the top of the generated script, the deck and PDF names relative to the script (so the delivery folder moves as a whole), the skill's `scripts/` directory, the embedded block version, the plugin version (when available), the block configuration and the exporter options (`--selector` from the block's `root`, `--size`). The generated script resolves the scripts directory through `--scripts`, then `NBG_DESIGN_SCRIPTS` (the same variable the workspace's `html-editor` skill uses), then the recorded directory; a directory that lacks `add-deck-menu.mjs` / `verify-deck.mjs` / `export-pdf.mjs` / `lib/` is an error naming the source and the path — no other location is tried. Before rewriting the deck it keeps `<deck>.backup-<stamp>.html` (`--no-backup` skips it). Exit codes mirror the exporter's: 0 rebuilt, 1 error or gate failure, 2 usage, 3 HTML rebuilt but no browser for the PDF.
- Refusals: a deck without the editor block (the generator has nothing to record), the old PDF-only block, and page-mode blocks (a page has no slide PDF; the `html-editor` skill's `add-editor.mjs` refreshes those). A malformed `--size` is an error.
- Rationale: the deck is a file that was handed over once, the tools evolve with the skill; a per-deck script that carries its own settings is what a recipient can run without knowing the skill, while `add-deck-menu.mjs` alone would leave the PDF stale and the verification unrun. Recording the paths rather than searching for them follows the no-fallback rule.
- Verification (2026-09-05): `test_scripts/rebuild-script-roundtrip.mjs` in the development workspace (30 checks on a real 15-slide deck: generation, `--check` both ways, an upgrade from a simulated v3 block with backup, verification and a 15-page PDF, another copy with `--no-pdf` / `--no-backup`, the three resolution sources and their errors, usage errors, the generator's refusals, a deck-mode configuration carried through the rebuild) passes. Record: `docs/nbg-design-docs/verification.md`.

### In-deck SVG editing (skill v1.18.0, block v12)
- Decision (user request, 2026-09-05): recipients of a deck can edit the inline SVGs it embeds (icons, diagrams, charts drawn in the deck) the way they edit text and shapes: right-click → *Edit SVG* (or double-click the selected SVG, or a part row in the Tree tab) starts a session on that `<svg>`; its parts (path, rect, circle, ellipse, line, polyline, polygon, text, image, use, g — nothing inside defs / clipPath / mask / symbol / pattern / marker / gradients / filter) are picked by a click (through the selected part's frame as well: a click without a drag picks the part underneath, a drag moves the selected part — user request, 2026-09-05), Shift+click (several parts, through the frame too — user request, 2026-09-05), Ctrl/Cmd+click (what is inside the smallest part under the pointer — a leaf alone, the members of a selected group when its frame is clicked; user request, same day, refined after a first version that selected the whole enclosing group; on HTML shapes Ctrl/Cmd+click now selects everything inside the shape under the pointer, its child shapes, and keeps the old pick-alone / cycle-outward behaviour only for a shape with nothing inside), Ctrl/Cmd+A / All (every top-level part), Tab / Shift+Tab or the toolbar's Parts list; a frame with eight handles (spanning the selection, a dashed mark per part) moves and resizes the selected parts together, arrows nudge in SVG units; the SVG row of the floating toolbar sets X / Y / W / H, fill, stroke, stroke width, opacity, the text of a one-run `<text>`, the drawing order, duplicates and deletes parts, and resets the SVG.
- Mechanism: geometry is computed in the part's parent user space by mapping the screen box through `parent.getScreenCTM().inverse()` (which holds at any artboard scale, verified at 1366×768) and written as plain attributes where they exist without a transform (x / y / width / height of a rect or image; x / y, cx / cy, x1…y2 for a pure move of text / use / circle / ellipse / line) and otherwise as a `matrix()` prepended to the part's consolidated transform — path data is never rewritten. Colours are presentation attributes, or the inline style property when the part already sets it. Every operation records the `<svg>` element's innerHTML as its single `html` edit, so the existing persistence, saved copy, per-slide discard and print paths apply unchanged; Reset SVG drops the record. Sessions are exclusive with text editing, shape selection, source apply, discard and print; the session class never enters a record. Fixes on the way: SVG `<text>` was a contenteditable target (it is not any more), an `<svg>` had no offset box and so was missing from the Outline and from Select all (`offW` / `offH`).
- Not done on purpose: no path-point editing (a viewer who needs that regenerates the deck), no rotation handle, no multi-part selection (Duplicate + Delete cover the common chart edits), no in-place typing on SVG text (the toolbar field edits it).
- Verification (2026-09-05): `test_scripts/svg-editor-roundtrip.mjs` (a synthetic chart SVG on slide 1 of the real 15-slide deck at a scaled viewport; 75 checks: menu entry, real-mouse picking (also through the frame of a selected group), Shift+click multi-selection (frame, marks, drag / fill / nudge / order / Delete on all, All, a group and its member), drag move / resize with attribute and matrix outcomes, toolbar fields, fills / strokes / opacity, inline-style parts, text, order, duplicate / delete, Tab / Esc / Enter, the one record, reload persistence, the saved copy, Reset SVG, the Tree route, the print path, the shape frame hand-over, the Outline label) passes; `deck-menu-roundtrip.mjs` (250 checks) and `html-editor-roundtrip.mjs` pass on the v12 block.
